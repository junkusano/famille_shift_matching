# 教訓リマインドの公開用候補の更新

## この変更で実装する範囲

記事生成の情報源同期後に、管理者向け教訓の原文と公開用要約の版を照合する。原文は社内限定のまま保持する。原文の本文・内容・取り込み元の版から指紋を作り、公開用レコードを `parent_knowledge_id` で結ぶ。

- 新規原文は、別の社内限定レコードを `needs_review` として登録する。原文をコピーしたり、自動的に公開承認したりしない。
- 原文が変わった場合は旧要約を公開対象から外し、新しい版を確認待ちにする。
- 同期済みのシートに存在しない行、変更前の版、承認が取り消された要約は、記事候補に入れない。画像・本文生成後にも公開直前に再確認する。
- 同じ版は一度だけ登録する。同時実行時の一意制約違反は重複として扱い、その他の保存失敗は成功扱いにしない。
- 1実行20件まで書き込み、残件は次回へ回す。ページ分割で全原文を確認する。
- 既存の手動承認済み要約は承認日時以後に原文が変更されていない場合に限り利用する。版を戻しても以前の承認は復活させず再確認する。

`knowledge_automation_runs.output_summary.lessonEditorial` に原文数、新規登録数、審査待ち数、承認済み数、旧版停止数、残件数を保存する。候補が採用されなかった場合も、一般化・審査待ちがあることをメッセージに含める。

## 確認・承認

既存の管理者ナレッジ編集画面で確認待ちレコードと参照元原文を確認し、`public_summary` に一般化した文章を登録する。個人情報・内部URL・社内固有スキルの説明を含めない。公開する場合は既存の公開要件（承認、公開区分、匿名化完了、個人情報なし）を満たす必要がある。

## 未実装の範囲

制限された原文を外部AIへ送り、自動一般化・審査する処理は含めていない。原文の外部処理の明示的な許可が別途必要。通常の記事生成の外部AI利用設定や、特定の8件の公開承認から、この許可を推定しない。

したがって、この変更だけで毎日の記事公開を保証しない。確認待ちから公開用要約へ進める工程が必要であり、既存の重複審査・外部根拠の確認も引き続き適用する。
