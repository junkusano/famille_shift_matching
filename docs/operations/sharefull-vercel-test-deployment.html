Sharefull Vercelテスト環境手順

本番Vercelとは分離したテスト環境、共有Runner、安全確認、応募・応募確定通知経路を確認するための手順

別Vercelプロジェクトcronなしコード実装済み・認証設定待ち
全体ロードマップ環境変数デプロイ応募通知ジョブ確認Runnercronガード
注意: テスト用応募イベントAPIとGASコードは実装済みです。デプロイ後にGASのScript Properties、テスト用LINE WORKS送信先・アクセストークンを設定して実送信を確認します。本番送信先を使った検証は行いません。

環境変数

SHAREFULL_RPA_MODE=test
SHAREFULL_TEST_DEPLOYMENT=true
SHAREFULL_AUTOMATION_CRONS_ENABLED=false
SHAREFULL_AUTO_POST_ENABLED=true
SHAREFULL_AUTO_POST_MODE=save
SHAREFULL_TEST_RUNNER_ID=sharefull-test-runner
SHAREFULL_TEST_GAS_TOKEN=<テスト用GASトークン>

SHAREFULL_AUTO_POST_MODE=saveにより、まずはSharefull画面で保存までを確認し、募集開始は行いません。SHAREFULL_TEST_GAS_TOKENはVercelとGASで同じ値を設定し、本番環境には設定しません。

デプロイ

vercel.test.jsonはcronを含みません。Vercel CLIでこの設定を明示して、既存のテスト用プロジェクトへデプロイします。

npx vercel deploy --prod --scope junkusanos-projects --yes --local-config vercel.test.json

テスト用プロジェクトはfamille-shift-matching-test、URLはhttps://famille-shift-matching-test.vercel.appです。Runnerのテスト設定ではこのURLとテスト用APIベースURLを使用し、本番URLを設定しません。

応募通知テスト

案件掲載後の応募・応募確定通知は、Sharefull画面をRunnerで監視せず、次の分離した経路で確認します。

Sharefull応募・応募確定
  → テスト用Gmailの対象ラベル
  → 時間主導トリガーのGoogle Apps Script
  → 求人ID・管理番号・応募者情報・applied / confirmedを検証
  → テストAPI（/api/rpa/sharefull/test-application）へ登録
  → GmailメッセージID・応募識別キーで重複除外
  → テスト用LINE WORKSグループへ通知

テスト用GASでは、対象送信元・件名・求人IDまたは管理番号と応募状態を検証し、SHAREFULL_TEST_GAS_TOKENをBearerトークンとしてテストAPIへ送信します。同じ応募識別キーはappliedからconfirmedへ更新し、APIが重複と判定したイベントは再通知しません。本番Gmail、本番GAS、本番LINE WORKS送信先、OAuth情報はテストと分離します。

テスト前のジョブ確認

テスト開始前に、Supabase SQL Editorで共有Runnerが取得する未完了ジョブ全体を確認します。

select id, job_type, status, target_runner_id, payload, created_at
from public.rpa_runner_jobs
where status in ('pending', 'claimed')
order by created_at asc;

本番用のpendingまたはclaimedが1件でもある間は、共有Runnerで実画面テストを開始しません。専用のテストRunnerであっても、テスト用送信先がテストGmail・テストLINE WORKSグループになっていることを確認します。

テスト用ジョブ登録後は、次でテスト用だけであることを確認します。

select id, job_type, status, payload->>'rpa_mode' as rpa_mode,
       payload->>'spot_offer_request_id' as request_id, created_at
from public.rpa_runner_jobs
where status in ('pending', 'claimed')
order by created_at asc;

Runnerについて

初回は専用Runnerを作らず、既存Runnerを使ってよい。ただし次の条件を満たす場合だけとします。

  • テスト中に本番の未完了ジョブが0件である。
  • 本番VercelのSharefull/Taimee自動処理を同時に動かさない。
  • テスト終了後に、未完了ジョブが残っていないことを確認する。
  • テスト用Gmailの処理済みラベル、GAS実行ログ、LINE WORKS通知件数を照合する。
  • 同じGmailメッセージを再処理してもLINE WORKSへ二重通知されないことを確認する。

これは初回の短時間テスト向けです。本番・テスト同時稼働では専用Runnerまたはキュー分離が必要になります。

cronガード

テストデプロイでは、次のRPA生成cronも環境変数で停止します。

停止対象目的
/api/cron/spot-offer-sync-checkSharefull同期・状態確認の自動ジョブ登録を停止
/api/cron/open-sharefull-jobsSharefull掲載ジョブ登録を停止
/api/cron/open-taimee-jobsタイミー掲載ジョブ登録を停止
/api/cron/rpa-scheduler汎用RPAジョブ登録を停止

停止時はジョブ登録を行わず、skipped: trueを返します。Vercel側でcronなしにする設定と合わせた二重防護です。
