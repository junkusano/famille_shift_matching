# 事務案件のSharefull連携

介護シフトと独立した事務案件を既存の本番キュー、Runner、Chrome拡張で掲載する。
`recruitment_kind=care` は既存の利用者スコープ・必要人数・シフト判定を保持する。

## 登録と適用範囲

- 事務案件は運用担当がservice_roleで、テンプレートと対応requestを`recruitment_kind=office`として登録する。通常のクライアントからこの区分へ切り替えることはDBトリガーが拒否する。
- 利用者ID・介護シフトIDはnull。資格不要・資格配列空の事務テンプレートを必須にする。
- 現段階は他媒体の既存確定枠を含めない「残り1枠」の募集だけを扱う。requestの`office_headcount=1`を必須にし、既存ワーカーの雇用状態は変更しない。複数残枠の同時制御は対象外。
- 日時・時給・交通費を実求人と照合する。求人・テンプレートの重複、募集中であること、残り枠を掲載直前にも確認する。過去メールを一括再送しない。

## 通常経路

1. 既存Cronが有効officeテンプレートだけを検出し、`sharefull.create_template`へ登録する。既存利用者の対象範囲は広げない。
2. 拡張0.3.58以降がoffice_capability=1を付けてデータを取得。旧版はAPI426で停止する。職種はオフィスワーク→事務・アシスタント、日本語入力・作業アシスタント。介護共通文面と資格質問を追加しない。
3. テンプレートID保存と審査完了を確認後、既存`sharefull.create_spot_offer`へ残り1枠を登録する。操作キーは`office:<request ID>`を使い、シフト番号との衝突を避ける。
4. 取得直前に日時・人数・時給・交通費・応募・手動停止を再確認。完了RPCで実求人ID・注文ID・掲載履歴を保存する。
5. Timeeの新着確定→既存GAS/API→通知→Sharefull停止、取消→既存CronのSharefull再掲載判定を利用する。シフト削除監視はofficeを処理しない。

officeのTimee再作成は介護シフトからのPAD再作成へ渡さない。Timee求人が終了した場合の再作成は元の事務求人・残枠を運用担当が確認する。
天白Runnerの接続・新拡張の読込確認が終わるまで作成ジョブを実行しない。テンプレート428828はコピー元として保持し、削除・置換しない。
