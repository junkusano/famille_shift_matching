Sharefull RPA 本番・テスト環境全体像

本番・テスト環境における案件同期、Sharefull掲載・クローズ、応募通知（Gmail→GAS→LINE WORKS）までの最新版構成

本番・テスト比較応募通知経路を追加確定テスト応募テーブル: sharefull_rpa_test_spot_offer_applications
環境境界共通構成TypeScript処理応募イベント応募通知掲載・クローズデータ分離要点
前提: これは本番環境とテスト環境を並べた現時点の全体図です。本番は通常運用（cron有効・本番Runner・本番通知先）、テストは分離運用（cron停止・テストRunner・テスト通知先）とします。GAS・LINE WORKSの送信設定や認証情報はこの資料では変更しません。

分離の原則: テスト処理は本番テーブル・本番Runner・本番Gmail・本番LINE WORKSへ接続しません。本番の運用を止めずに検証できる専用境界を維持します。

本番の通常運用

MyFamilleの案件・シフト → 本番cron → 本番テーブルを参照 → rpa_runner_jobs / rpa_command_requests → tenpaku-rpa-02またはタイミーPAD → Sharefull・タイミー。Sharefull応募は本番Gmailから本番GASを経由して本番LINE WORKSへ通知します。

テストの手動運用

テストVercel → テストテーブル → 専用Runner sharefull-test-runner → テスト用Chrome拡張 → Sharefull。応募通知はテストGmail → テストGAS → テストLINE WORKSへ送ります。

1. 共通処理の全体構成

外部・業務データ MyFamille ── shift（シフト） │ └──── 案件・募集情報（spot_offer_request_table） │ │ 案件の中心レコード ▼ ┌────────────────────────────┐ │ spot_offer_request_table │ │ id / shift_id │ │ 日付・時間・金額・媒体ID等 │ └──────────────┬─────────────┘ │ request_id ┌──────────────┴──────────────┐ ▼ ▼ spot_offer_application_events spot_offer_applications 重複防止用の受信イベント 媒体ごとの応募状態 └──────────────┬──────────────┘ ▼ TypeScript処理・cron/API │ ▼ PAD / Chrome Runner │ ▼ Sharefull画面 │ 応募・応募確定 ▼ Sharefull応募通知メール │ ▼ テスト用Gmail │ ▼ テスト用GAS（取得・検証・重複防止） │ ▼ テスト用LINE WORKS

案件テーブル

案件の中心レコード。シフト、掲載情報、Sharefullの求人ID・管理番号・状態を保持します。

応募イベント

媒体から受信したイベントを保存し、provider + event_idで重複を防止します。

応募テーブル

媒体ごとの応募状態を保持します。テストモードでは専用テーブルを利用予定です。

応募通知

Sharefullの応募メールをGASが取得・検証し、重複を除外してLINE WORKSへ通知します。Runnerの監視処理とは別経路です。

5. 応募・応募確定通知（Gmail → Google Apps Script → LINE WORKS）

1Sharefullで応募

掲載済み求人に応募が発生

2Gmailで受信

応募・応募確定メールを受信

3Google Apps Scriptがチェック

送信元・件名・求人ID・管理番号・本文を確認

4応募状態を判定

appliedまたはconfirmedとして登録・更新

5重複防止

Gmail message IDと応募識別キーを記録

6LINE WORKS通知

テスト／本番の対応グループへ通知

処理テスト環境本番切替条件
メール取得テスト用Gmailアカウント／専用ラベル対象メール、送信元、件名、求人IDの確認が完了
判定・記録GASのPropertiesService等に処理済みGmail message IDを記録し、同一応募の状態を更新応募から応募確定への更新と、再実行時の重複通知がないことを確認
通知先テスト用LINE WORKSグループ本番LINE WORKSへの切替前に送信内容・権限・再送方針を確認
安全条件: テスト中は本番Gmailを検索せず、本番LINE WORKSへ送信しません。応募メールはapplied、応募確定メールはconfirmedとして同じ応募識別キーを更新します。メール本文・アクセストークン等の機密情報はログに残しません。

共有Runnerへの安全策

テストは専用Runner sharefull-test-runner を使用します。やむを得ずrpa_runner_jobsを共有する場合は、本番のpending・claimedを0件にし、本番cronを停止してから実行します。

テスト用Vercel: https://famille-shift-matching-test.vercel.app ／ テストモード: SHAREFULL_RPA_MODE=test ／ 本番モード: SHAREFULL_RPA_MODE=production
